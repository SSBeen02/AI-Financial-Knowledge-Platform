# 최신 퀴즈 기반 학습노트 동기화 및 검증

기준일: 2026-11-10
반영 위치: C:/Github/AI-Financial-Knowledge-Platform/학습노트 업로드
기준 퀴즈: 같은 저장소의 quiz-upload. 원본 퀴즈 폴더는 변경하지 않았다.

## 변경

- 최신 퀴즈 생성·형식 검증·재시도·최초 제출 고정·문체 처리를 학습노트 패키지의 공통 코드에 반영했다.
- QuizSubmission에 UNIQUE(quiz_set_id)를 추가했다. 동일 세트를 다른 키로 제출해도 기존 최초 결과를 사용한다.
- 최신 DB 시작 검사를 반영했다. 기존 DB에 최초 제출 유일 제약이 없으면 안내 오류로 중단하며 데이터를 자동 변경하지 않는다.
- quiz_002_first_submission.sql 및 오프라인 SQLite 마이그레이션 도구를 포함했다. 기존 데이터 삭제·기존 DB 마이그레이션은 실행하지 않았다.
- 최신 일반 퀴즈 화면의 답안·문항 위치·제출 키 복원을 반영하면서 기존 mode=review 분기를 유지했다.
- QuizReview 모델·FK·복습 API, 조회 인덱스, 현재 개념 상태 조회·등록 함수, 기본 가나다순/최신순 선택, 회차 선택·최신 복습 5개 표시를 보존했다.
- 현재 인증 의존성·사전테스트 라우트가 들어 있는 main.py를 유지했다.
- 새 RLS 차단 SQL은 포함하지 않았고 공유 DB 권한을 바꾸지 않았다.

결합 시나리오에서는 동일 세트의 다른 키 재제출이 최초 결과를 반환하는지, 새 학습 세트가 새 회차로 나타나는지, 두 번의 복습이 quiz_reviews에만 저장되고 원본·회차·통과 결과가 유지되는지 확인했다. 복습 중 학습 관리 결과 보고가 호출되지 않는 것도 확인했다.

처음 실행한 94건 중 4건은 예전 규칙에 맞춘 기대값과 최신 규칙이 달라 실패했다. 퀴즈 전용의 두 테이블 기대값은 복습 테이블을 포함하도록 수정했다. 중복된 옛 퀴즈 시험은 최신 퀴즈 시험으로 대체하고, 학습노트 전용 6건을 보존했다. 이 중 27문항 조회 fixture는 동일 fake 문항을 반복하므로 그 시험에서만 출제 중복 검사를 대체했다. 실제 출제 중복 거부는 최신 전용 7건에서 확인했다. 이력 필터·문항 수 검증은 삭제하지 않았다. 최종 결과는 79/79이며 최초 94건 전부가 통과했다고 쓰지 않는다.

## 개발용 브라우저 확인

- 일반 퀴즈: O/X 단일 표시, 문항 전환, 새로고침 시 선택한 답·현재 문항 복원, 3문항 제출·통과 표시 확인.
- 일반 퀴즈 제출 후 학습노트: 한 개념 안에 1회차 미통과·2회차 통과 표시 확인. 같은 제목의 왼쪽 항목을 중복 생성하지 않음.
- 복습 모드: 원본 Q2 조회, 제출 전 정답·해설 숨김, X 제출 후 정답·해설·저장 안내 확인.
- 복귀: Stage 1·전체 풀이·개념 목록 1페이지 초기화 확인.
- Stage 5 재선택: 최초 Q2는 여전히 오답·해당 회차 미통과, 복습 기록에는 정답 X가 추가된 상태 확인.
- 최초 검사와 중단 후 재개 검사는 서로 다른 임시 DB다. 스크린샷에 서로 다른 임시 제출 ID가 있을 수 있으며 실제 사용자 기록이 아니다.

## 반영 확인과 제한

- 검사한 source를 manifest의 해시로 확인한 뒤 실제 저장소에 17개 파일 반영. 원래 대상 파일의 변경 여부도 검사했다. 백업은 before_apply에 보관했다.
- 자동시험은 임시 SQLite·HTTPX·모의 AI 및 학습 관리 대역을 사용했다. 실제 로그인 토큰·실제 챗봇·보상·Supabase 동시 제출을 이번 실행으로 검증했다고 주장하지 않는다.
- 기존 PostgreSQL 유일 제약 적용은 퀴즈 쪽 검증 문서의 사용자 확인 기록을 참조하며, 이번 작업에서 운영 DB를 다시 조사하거나 변경하지 않았다.
- 운영 RLS, 최종 프론트, 3초 및 원문 대량 이력 성능은 별도다.
- 퀴즈 결과 선저장 후 학습 관리 보고 방식은 유지한다. 여러 모듈의 단일 트랜잭션은 아직 구현 완료로 표시하지 않는다.
- 커밋·푸시·배포는 하지 않았다.
