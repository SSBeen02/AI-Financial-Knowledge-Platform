## 사전테스트 성능안과 완료 기준

현재 시험 계정 `sdsd`는 이미 최초 사전테스트를 제출하고 리포트가 생성된 상태다. 이 계정의 화면에서는 최초 시작·답안 제출·리포트 실패 재생성을 다시 실행할 수 없었다. PT-FR-02, PT-IR-03, PT-QR-01의 최신 배포 판정을 위해서는 최초 응시 전용 시험 계정 또는 해당 경로의 배포 로그가 필요하다. 리포트 화면만으로 실행 모드나 생성 시간을 추정하지 않는다.

- **리포트 생성:** PT-QR-01의 기존 요구인 *답안 제출부터 리포트 성공 표시까지 60초 이내*를 합격선으로 확정한다. 생성 실패는 30초 안에 `failed`가 표시되고 같은 응시에서 재생성할 수 있어야 한다. 28초는 서버 내부 생성 예산이며 사용자 화면의 60초 기준과 구분한다.
- **상태·결과 조회:** p95 3초 이내를 설계 목표로 둔다. 브라우저 요청 시작→응답 본문 수신과 화면 표시를 각각 기록한다.
- **답안 제출 자체:** 리포트 생성과 결합된 요청이면 60초 종단 기준으로 평가한다. 비동기 제출이면 제출 접수 p95 5초 이내, 리포트 완료 60초 이내를 각각 평가한다. 실제 API 구조를 확인한 뒤 한 방식으로 고정한다.
- **측정과 판정:** 같은 배포 버전에서 정상 생성과 실패·재생성 경로를 각각 수행한다. 요청 실패, 중복 응시, 리포트 누락은 0건이어야 한다. 표본이 적으면 개별 소요 시간만 보고하고 p95 통과로 표기하지 않는다.
