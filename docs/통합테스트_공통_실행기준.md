# 통합테스트 공통 실행 기준

## 에이전트의 첫 응답

이 문서를 받은 에이전트는 **다른 조작보다 먼저 사용자에게 `이번 통합테스트 실행 담당자는 박서현인가요, 안유빈인가요?`라고 질문하고 답을 기다린다.** 계정 표시명 `김아주`는 테스트 계정 이름이지 담당자 이름이 아니다. 대화 맥락이나 파일명으로 담당자를 추정하지 않는다. 두 이름 외의 답이 오면 담당 범위를 확인한다. 담당자가 확인되기 전에는 사이트 로그인 요청, 브라우저 조작, DB 상태 변경, 개념 시험을 시작하지 않는다.

답이 `박서현`이면 Stage 3→4→5 개방 확인까지, `안유빈`이면 박서현의 완료 기록과 Stage 5 시작 화면을 대조한 후 Stage 5 최종 완료까지 담당한다. **박서현 결과가 아직 없으면 안유빈 실행은 대기**하며 Stage 3·4를 대신 조작하지 않는다. 이어하기 요청에서는 먼저 저장된 실행 기록의 담당자와 이번 사용자 답을 대조한 뒤 같은 지점에서 재개한다.

## 실행 정보와 순서

- 실행 ID: `SYS-IT-2026-01` (계속 유지)
- 배포 사이트: https://plant-pin-65764387.figma.site/
- 테스트 계정 표시명: `김아주`. 로그인은 사용자가 직접 수행한다. 계정이나 실행 ID를 임의로 바꾸지 않는다.
- **1차: 박서현 — Stage 3, Stage 4.** Stage 4를 마치고 Stage 5 개방 상태를 확인한 뒤 기록한다.
- **2차: 안유빈 — Stage 5.** 박서현의 Stage 5 시작 상태 기록과 실제 화면을 대조한 뒤 진행한다. 박서현이 완료하기 전에는 Stage 5를 시작하지 않는다.
- 코드 수정, 배포, 커밋, 푸시는 이 시험의 범위가 아니다. 사용자가 이미 확인한 로컬 회귀 **135+6+54=195개 통과**는 재실행하지 않는다. `워킹푸어`도 재시험하지 않는다.
- 담당자 확인 뒤 사이트 접근이 필요하면 사용자에게 직접 로그인을 요청한다. 자격 증명을 입력하거나 저장하지 않는다.

## 인수 시작 상태

2026-11-12 마지막 확인 기준: Stage 3 **통과 0/50, 학습중 0, 미학습 50**, 캐릭터 `김아주`, 신분 **양반**, **700엽전**, 세 번째 장의 진행률 0%. 마지막 실제 통과 개념은 Stage 2 `연금저축`이다. 마지막 화면은 학습노트의 Stage 2 목록이며, 그 목록에는 4개 개념·12개 퀴즈 기록이 있었다.

시작할 때 사이트에서 계정·Stage·세 상태 개수·엽전·이야기 진행률을 다시 확인한다. 값이 다르면 어떤 값이 언제 달랐는지 기록하고 원인을 확인한 뒤 진행한다. Stage 5 시작 상태는 아직 확정되지 않았으며, 박서현의 Stage 4 종료 기록이 기준이 된다.

## 검증 범위

각 Stage에서 서로 다른 하위 범주를 우선하여 **4개 개념만 실제 사이트에서 상세 검증**한다. 개념 이름과 `concept_id`는 Stage 카탈로그와 대조해 기록한다. 이미 학습중인 개념이 있다면 먼저 마친다.

상세 검증 개념마다 다음을 수행한다.

1. 미학습 상태와 추천 목록을 확인하고, 키워드 선택 또는 자유 질문 후 학습 시작 흐름으로 들어간다.
2. 실제 질문과 후속 질문을 보낸다. 화면의 첫 글자 표시, 완성된 답변, 출처, 질문과 답변의 관련성을 확인한다. 시간을 실제로 측정하지 않았다면 성능 통과로 쓰지 않는다.
3. 학습중 상태를 확인하고 `학습 완료 · 퀴즈로`를 누른다. 생성된 **3문항을 실제로 읽고** 답안을 제출한다. attempt, 각 문항 답안, 점수, 채점 피드백, 최종 통과 여부를 기록한다. 미통과 시 실제 재학습 흐름으로 해결한다.
4. 학습 화면의 통과·학습중·미학습 수, 추천 제외, 학습노트의 풀이 기록, 메인 화면의 엽전·이야기 반영을 확인한다. 메인 상태가 늦게 갱신되면 지연 전후 값을 모두 기록한다.

**나머지 개념은 사용자가 지정한 방식대로 백엔드에서 완료 처리하여 Stage 전환을 검증한다.** 이 개념들을 실제 질문·퀴즈로 검증한 것처럼 기록하지 않는다. 처리 전에는 같은 계정과 현재 Stage, 상세 검증 4개 통과, 학습중 0, 잔여 개념 수, 게임 진행 수를 확인한다. 처리 뒤에는 개념 진행 상태와 단계 완료 이벤트·게임 반영을 확인하고 사이트를 다시 열어 다음 Stage를 대조한다. 상태가 예상과 다르거나 처리 절차의 접근 권한이 없으면 임의 우회하지 말고 `차단`으로 기록한다. Stage 5에서도 같은 방식으로 잔여 개념을 완료 처리한 뒤 **최종 완료 화면**을 확인한다.

Stage 3→4와 Stage 4→5의 전환은 박서현이, Stage 5 최종 완료는 안유빈이 확인한다. 경계 직후와 재진입 후의 Stage·통과 수·엽전·이야기·완료 안내를 비교한다. 백엔드 완료 처리로 확인한 전환은 `백엔드 보조 전환 검증`이라고 표기하며, 마지막 개념을 UI 퀴즈로 통과한 검증과 구분한다.

## 앞선 시험에서 확인된 사항

- Stage 1→2와 Stage 2→3 전환은 확인됐다. Stage 1의 잔여 12개, Stage 2의 잔여 36개는 **백엔드 완료 처리**했으며 UI 질문·퀴즈 검증 건수가 아니다.
- Stage 2의 상세 검증 4개 `복리이자`(`sisa_1237`), `예금자보호`(`sisa_1874`), `상장지수펀드`(`sisa_1410`), `연금저축`(`sisa_1852`)은 모두 첫 시도 3/3 통과했고 학습노트에 총 12문항이 기록됐다.
- 열린 결함: `렌트 푸어` 재학습에서 이전 대화 미표시(IT-02), 재로그인 후 Stage 3의 `복리이자` 자유 대화 미표시(IT-05), `연금저축보험`과 `연금저축펀드` 비교 후속 질문에 관련 없는 일반 문장만 반환. `연금저축` 첫 답변은 세액공제 한도를 400만 원과 600만 원으로 함께 언급해 기준이 불명확했다.
- 전환 직후 메인 화면의 엽전·이야기 수치가 잠시 이전 값으로 보인 사례가 있었다. 최종 동기화 값과 초기 값을 함께 기록한다.

## 기록과 인계 형식

담당자가 확인되면 **사이트 조작 전에** 이 문서가 들어 있는 저장소의 Git 루트를 확인하고, **그 Git 루트의 `docs/` 폴더에만** 자신의 실행 기록을 생성하거나 이어 쓴다. Windows의 현재 저장소 기준 경로는 `D:\GitHub\AI-Financial-Knowledge-Platform\docs\`이다. 다른 작업 폴더에서 실행 중이어도 현재 작업 폴더의 `docs/`나 별도 프론트 저장소에 저장하지 않는다.

- 박서현 결과: `<저장소 Git 루트>/docs/통합테스트_SYS-IT-2026-01_박서현_실행.md`
- 안유빈 결과: `<저장소 Git 루트>/docs/통합테스트_SYS-IT-2026-01_안유빈_실행.md`

이 Markdown 파일은 선택 사항이 아닌 **필수 시험 산출물**이다. 두 담당자는 서로의 파일을 덮어쓰지 않는다. 첫머리에 담당자, 실행 ID, 테스트 계정 표시명, 사이트 URL, KST 시작 시각, 브라우저, 화면에서 확인한 빌드 정보가 있으면 적는다. 기록 파일을 생성·수정할 수 없거나 저장소 Git 루트를 확인할 수 없으면 시험을 시작하거나 계속하지 말고 `기록 파일 저장 차단`으로 사용자에게 알린다.

각 개념에는 `Stage / 이름 / concept_id / 하위 범주 / attempt / 질문·후속 질문 / 출처 / 3문항 답안·점수 / 최종 상태 / 학습노트·게임 반영 / KST 시각`을 적는다. IT 항목은 `통과·실패·차단·미실행` 중 하나로 표시하고 화면에서 본 근거와 재현 순서를 적는다. 실패·차단·미실행은 통과 수에 넣지 않는다. 비밀번호, 토큰, 사용자 식별자는 기록하지 않는다.

**개념 하나를 마칠 때마다** 해당 파일에 결과를 추가한다. Stage 전환, 결함 발견, 중단 지점도 즉시 추가한다. 중단·담당 범위 완료 전에 파일을 다시 읽어 마지막 기록이 실제로 저장됐는지 확인하고, 최종 응답에는 저장한 파일 경로와 마지막 기록 상태를 함께 적는다. 응답만 남기고 파일 저장을 생략하지 않는다.

박서현은 Stage 4 종료 후 **Stage 5의 시작 수치, 신분·엽전·이야기, 마지막 상세 통과 개념, 백엔드 처리 수, 열린 결함, 안유빈의 다음 조작**을 자신의 기록에 남긴다. 안유빈은 그 수치를 현재 화면과 대조한 뒤 시작한다.

### 토큰 부족 시 중단·재개

남은 토큰으로 다음 개념의 질문→퀴즈→결과까지 마치기 어렵다고 판단하면 **새 개념을 시작하기 전에** 실행 기록 파일의 맨 끝에 아래 체크포인트를 저장하고 다시 읽어 확인한 다음 `중단-토큰 부족`으로 끝낸다. 이미 개념을 시작했다면 가능한 한 그 개념의 현재 서버·화면 상태를 확인해 파일에 기록한 뒤 멈춘다. 작업량만을 이유로 전체 범위를 완료 처리하거나 다음 담당자에게 넘기지 않는다.

```text
실행 ID: SYS-IT-2026-01
담당자:
중단 시각(KST):
현재 Stage / 통과·학습중·미학습 / 진행률:
계정 표시명 / 신분 / 엽전 / 이야기 장·진행률:
마지막으로 완료한 개념·ID / attempt / 퀴즈 점수:
현재 화면(메인·학습·퀴즈·학습노트), 열려 있는 개념과 질문·퀴즈 상태:
이 Stage의 상세 검증 완료 개념 수(목표 4) / 백엔드 완료 처리 수:
확인한 전환 / 아직 확인하지 않은 전환:
IT-01~07 각각의 통과·실패·차단·미실행 상태와 남은 조작:
재현된 결함과 마지막 화면 근거:
재개 직후 첫 조작 하나:
```

재개 시에는 같은 실행 ID·담당자 기록을 읽고, 사용자가 직접 로그인한 같은 테스트 계정에서 화면 상태를 체크포인트와 대조한다. 서버에서 이미 통과한 개념과 퀴즈는 반복하지 않는다. 차이가 있으면 원인을 확인해 기록한 뒤 이어서 진행한다. **완료 판정은 담당 범위의 상세 4개씩, 잔여 개념의 백엔드 처리, Stage 전환 또는 Stage 5 최종 상태와 미완료 IT 분류가 모두 기록됐을 때만** 내린다. 열린 결함은 전체 통합시험 통과로 합산하지 않는다.
