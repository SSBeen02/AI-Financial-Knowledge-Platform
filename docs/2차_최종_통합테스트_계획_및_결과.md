## 목적과 범위

1차에서 발견한 결함의 **수정·협약 결과를 실제 배포 버전에서 확인**하고, 학습→퀴즈→진행·보상→재진입의 핵심 흐름을 끝까지 검증한다. 특히 1차에서 미실행한 **IT-08 배포 성능시험**을 독립 판정한다. 1차의 Stage 전환 증거와 로컬 195개 회귀 통과를 2차 통과 증거로 재사용하지 않는다. 로컬 회귀 전체 재실행은 기본 범위에서 제외한다. 수정 코드와 배포 버전의 연결 확인에 필요한 표적 자동시험이 있을 때만 실행 결과를 첨부한다.

이 문서는 1차의 담당자 순서나 `김아주` 계정 상태를 새 실행의 필수 조건으로 복사하지 않는다. 이미 완료된 계정으로 미학습·재학습 경로를 검증할 수 없으므로, 계정별 시작 상태를 먼저 확인하고 가능한 경로만 수행한다. 진행 기록을 초기화하거나 다른 계정의 결과를 혼합하지 않는다.

## 공통 실행 규칙

- 배포 버전 또는 API 응답 헤더의 식별자, 접속 URL, 계정 표시명, Stage의 통과·학습중·미학습 수, 엽전·이야기 진행률을 시작·종료 시각과 함께 기록한다. 빌드 식별자를 확인할 수 없으면 `버전 미확인`으로 적는다.
- 질문·답변 본문과 출처, 퀴즈의 실제 문항·선택 답·채점·attempt, 전후 상태를 기록한다. 비밀번호, 인증 토큰, 사용자 UUID는 기록하지 않는다.
- 결함은 KST 시각, 재현 순서, 기대/실제, 화면 또는 응답의 증거, 영향 범위, 재시도 결과를 남긴다. 항목 판정은 `통과 / 실패 / 차단 / 미실행`만 쓴다.
- 상태 변경 시험은 검증용 계정에서만 수행하고, 서버 완료 API로 만든 상태는 `백엔드 보조`로 표시한다. UI 퀴즈를 통과한 것처럼 기록하지 않는다.
- 필수 기능 결함이나 IT-08 기준 미달이 남으면 전체 판정은 `실패`; 환경·접근·합의 기준 부재로 필수 항목을 끝내지 못하면 `차단`; 모두 충족하고 증거를 저장한 경우에만 `통과`로 한다.

## IT-08 배포 성능시험 — 우선 실행

**측정 대상은 사전진단, 학습 모듈, 동적 퀴즈, 학습노트, 게임 상태조회, 게임 보상·구매의 여섯 범주**다. [UT-13](../rag/chatbot_module/GUIDE/UT13_MEASUREMENT.md)의 로컬 156회 첫 글자 20초 이내 결과는 참고값일 뿐, 배포 IT-08 결과가 아니다.

**2026-11-26 실행 범위 조정:** 새 배포 `53379e8`에서 같은 학습 질문 3회·다른 질문 1회를 측정한 뒤 학습 모듈 성능 반복은 우선 중단한다. 퀴즈 성능 추가 반복도 종료하고 이후에는 생성 막힘 재발 여부만 확인한다. 사전진단 답안 제출 시간은 후속 시험으로 미룬다. 게임 상태조회·보상·구매 성능과 데이터 정합성을 우선 확인한다. 기존 관찰값과 미계측 사실은 유지하며, 보류한 항목을 통과로 판정하지 않는다.

### 계측과 표본

1. 배포 버전, 브라우저·OS, 시험 지역·회선, 시각, 인증 계정, 서버 콜드/웜 상태를 기록한다. 개발자 도구 Performance/Network 또는 브라우저 자동화의 고해상도 시계로 `전송 클릭`, `첫 비공백 답변 글자 화면 표시`, `답변/출처 완료`, `입력·완료 버튼 재활성화` 시점을 **같은 시계**로 잰다. 첫 SSE `token.delta`가 화면 글자보다 먼저 오면 두 값을 구분해 저장한다.
2. 학습 모듈은 경제 개념 질문·맥락 후속 질문·비경제 범위 밖 질문 **각 10회, 총 30회**를 제안한다. 나머지 범주의 독립 작업별 p95 판정에는 **각 30회 이상**을 제안한다. 퀴즈 생성·진단 제출·구매처럼 비용이나 상태 변경이 있는 작업은 서로 다른 시험 데이터와 검증 계정을 사용하고, 수행 가능한 표본 수가 30회보다 적으면 p95를 참고값으로만 표시한다. 첫 1회는 콜드 경로, 나머지는 웜 경로로 구분한다. 재시도와 실패도 원표본에 남긴다.
3. 요청별 첫 글자 시간, 완료 시간, 버튼 재활성화 시간, HTTP 상태·스트림 종료 여부, 오류, 답변·출처 표시 여부를 기록한다. 동일 질문 반복에 따른 캐시 효과를 구분한다. 순차 요청을 기본으로 하고 동시 사용자 부하는 별도 합의가 있을 때만 수행한다.
4. 원시 데이터에서 표본 수, 성공률, 중앙값, p95, 최대값을 유형별·전체로 계산한다. p95는 오름차순 `ceil(0.95 × n)`번째 값으로 계산한다. 타임아웃·요청 실패·답변 누락은 실패 건수로 집계하고 지연 통계에서 제외했다는 사실을 명시한다.

### 판정 기준

아래는 **팀 확정 전 제안 기준**이다. 숫자는 배포 측정 결과가 아니며, 요청 특성과 1차 결함 및 기존 게임 목표를 토대로 정한 설계 목표다. 게임의 기존 목표(`상태 조회 p95 3초`, `보상·구매 p95 5초`, `핵심 데이터 오류 0건`)와 권장값(`상태 평균 300ms·p95 1초`, `보상 평균 500ms·p95 2초`)을 구분한다. 2차 판정에는 팀이 선택한 목표 열을 먼저 고정한다.

| 범주 | 2차 제안 목표 | 측정 경계·근거 |
|---|---:|---|
| 사전진단 | 상태·결과 조회 p95 ≤ 3초; 답안 제출→결과 표시 p95 ≤ 5초 | 조회와 제출을 별도 집계. 서버 처리와 화면 표시 시간을 함께 기록 |
| 학습 모듈 | 첫 화면 글자 p95 ≤ 10초·개별 ≤ 20초; 답변·출처 완료 p95 ≤ 30초·개별 ≤ 60초; 학습 상태 조회 p95 ≤ 3초 | 질문 클릭→첫 비공백 글자/완료, 상태 조회 요청→응답을 각각 계측. 답변·오류 종료 후 입력·완료 버튼은 2초 안에 활성화 |

| 학습노트 | 목록·풀이 기록 조회 p95 ≤ 3초 | 학습노트 진입/기록 선택→내용 표시. 기록 누락·중복 0건 |
