# 사전테스트 미구현 요구사항 보완

기준: 별첨 4 요구사항 분석서. 설계서 1.3에서 명시적으로 대체한 방식은 유지하고, 미구현·추가 필요 사항을 구현한다.

## 구현

| 항목 | 보완 내용 | 코드 |
|---|---|---|
| PT-FR-02 최초 1회 | 사용자별 기존 응시 재사용. pending 이어서 응시, 제출 후 기존 결과 이동. 메모리 잠금 및 Supabase 트랜잭션 잠금으로 여러 서버의 동시 시작 방지. 과거 중복은 제출된 응시 우선 | repository.start_once, DiagnosticService.start, POST /diagnostics |
| PT-FR-02 출제 순서 | 공개 문항을 Stage1→4로 정렬. 기존 문항 ID·정답·채점 규칙은 유지 | STAGE_DOMAINS, DiagnosticService.start |
| PT-QR-03 재생성 제한 | 최초 생성 제외 최대 3회. 실제 failed→processing 접수만 횟수 증가. 소진 시 429. 사용자·상태·생성 회차 조건부 갱신 | prepare_report_retry, update_attempt |
| PT-QR-03 제출 시각 | 최초 submitted_at 보존, report_started_at으로 재생성 시간 검사 | DiagnosticService, SQL |
| PT-QR-05 로그 | LLM 입력·프롬프트와 구조화 응답 로깅. API 키·토큰·사용자 ID는 포함하지 않음. 교육용 선택·채점 정보가 있으므로 로그 접근·보관 제한 필요 | llm_report, report_parallel |
| PT-QR-06 안전성 | 투자 실행 권유·수익 보장 금지 프롬프트, 출력 규칙 검사. 검출 시 설명 미저장·failed, 점수 유지. 고정 disclaimer 응답 및 개발 화면 표시 | report_safety, generate_report, ReportResponse, index.html |

규칙 등급·3개 리포트 섹션·하오체·5개 병렬 작업·학습 상태 자동 연결 제외·30초 타임아웃/28초 LLM 예산·사용자 재생성 정책은 유지한다.

## 검증

- 자동 테스트: 7개 파일, 62개 시험. `requirements-controls-retest.log`가 최종 실행 기록이다. 최초 61개에서 로컬 하오체 회귀 시험 1개를 추가했다.
- 추가 시험은 최초·동시 시작, 사용자 구분, 제출 후 재응시 방지, 과거 중복 우회 차단, 재생성 횟수·동시 요청, 최초 제출 시각, 이전 생성 결과 차단, 안전 표현 허용·권유 표현 차단, 점수 유지, Supabase RPC·조건부 필터 및 HTTP 201/200/429 계약을 포함한다.
- API 테스트는 메모리 저장소와 가짜 LLM을 사용한다. Supabase 어댑터 시험도 가짜 클라이언트다.
- 화면 JavaScript 문법 검사 실행. 배포 사이트를 변경하거나 최신 화면 전체 흐름을 실행한 것은 아니다.

## 배포 전 필수 적용·통합 확인

1. 기존 Supabase에 `sql/002_single_attempt_retry.sql` 적용. 신규 DB는 기본 SQL 다음 증분 SQL을 적용한다. 기존 데이터를 삭제하지 않는다.
2. 사용자 SQL 적용 후 실제 Supabase 기능 47개 검사 통과. 독립 DB 연결에서 기존 응시 재사용, 동시 최초 시작, 재생성 3회 제한, 채점 보존을 확인했다. 실제 로그인은 별도 통합 범위다.
3. 공통 인증 함수로 실제 로그인 사용자 ID 전달, 운영 DEV_MODE=false, HTTPS 및 프론트의 고지·재생성 버튼 연결은 설계서 1.3 (9)의 통합 책임을 유지한다.
4. 최종 코드의 실제 OpenAI·Supabase 재측정을 사례별 3회, 총 9회 수행했다. 평균 생성·저장 시간은 만점 8.267초, 부분 오답 16.123초, 전부 오답 18.879초. 자세한 품질·측정 제한은 current-code-retest-20261110/검증결과.md를 따른다.
5. 투자 권유 검사는 알려진 표현을 차단하는 규칙이며 모든 변형·문맥의 완전한 판별을 보장하지 않는다. 실제 출력 표본 검토와 구분한다.
6. 동시 사용자 30명 성능·실제 로그인·배포 화면의 답안 복원·팀 문항 내용 검수는 이 자동 테스트 통과로 완료 판정하지 않는다.

커밋·푸시는 실행하지 않는다.
