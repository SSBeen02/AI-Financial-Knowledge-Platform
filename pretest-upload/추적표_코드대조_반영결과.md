# 사전테스트 추적표 — 코드 대조 및 보완 결과

기준일: 2026-11-08

사용자가 제시한 추적표의 **설계 반영 열**을 구현 기준으로 삼았다. 분석서 요약 열은 과거 요구사항을 보존한다. 일부 반영·변경 반영은 전체 요구사항 충족과 구분한다. 다른 팀 모듈과 실환경 전체를 이번 자동 시험으로 검증한 것은 아니다.

## 이번 코드 보완

- `services/question_bank.py`: 지정된 영문 도메인 4종, 영역별 6문항·총 24문항, 4지선다, 공백 보기 금지, 핵심 개념 중복을 파일 로드 시 검증한다. 기존 필수 필드·문항 ID·정답 번호·해설 검증은 유지한다. 문항 데이터 자체는 바꾸지 않았다.
- `services/diagnostic_service.py`, `services/report_parallel.py`: 타임아웃 오류의 ‘목표 시간’ 표현을 ‘처리 기한’으로 바로잡았다. 30초 처리 기한과 최대 28초 LLM 예산은 유지한다.
- `tests/test_traceability.py`: 잘못된 문제은행 11가지 입력, JSON 왕복, 등급 및 50·70점 경계, 다른 사용자의 GET·제출·재생성 404, 리포트 실패 시 전체 채점 데이터 보존을 시험한다. 6개 test 메서드 내부에 경계별 하위 시험을 포함한다.

원본 사전테스트 폴더에서 전체 50개 통과. 외부 API를 호출하지 않고 메모리 저장소와 모의 LLM을 사용했다. 실행 기록은 `unittest-traceability-latest.log`에 저장한다. Git 연결 폴더의 검증은 별도 로그에 기록한다.

기존 실제 OpenAI 투자 권유 시험 결과는 `PT-UT-12-20261103/검증결과.md`를 참고한다. 이번 변경에서는 유료 OpenAI 호출이나 실 Supabase 변경을 새로 실행하지 않았다.

## 추적표에 필요한 최소 문구 갱신

- PT-QR-05 설계 반영: “채점·리포트 생성·저장소 모듈 분리, 자동 테스트 50개. LLM 모듈은 공유하지 않음. 로그는 시간·토큰·요청 ID·상태·진단 ID·오류 정보 중심으로 기록하며 전체 요청·응답 본문은 기록하지 않음.”
- PT-QR-04 설계 반영: “JSON 파일 기반 문제은행 로드 및 직렬화 호환, REST API, 백그라운드 리포트 생성. 전용 import/export API·화면은 없음.” 전용 기능이 분석서 의도였다면 상태는 일부 반영으로 유지해야 한다.
- PT-UT-12 상태: “완료(실제 생성 3건 표본 기준 통과)”. 금지 규칙·고지 구현 완료로 바꾸지 않는다.
- 그래프·실 인증·공유 LLM·최초 1회 제한·재생성 횟수 제한은 미완성 범위를 숨기거나 ‘전체 충족’으로 표시하지 않는다.
