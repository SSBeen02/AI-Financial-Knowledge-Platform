## DB 마이그레이션과 후속 확인

- PostgreSQL용 sql/quiz_002_first_submission.sql 작성. 중복 기존 제출이 있으면 전체 중단하며 삭제하지 않음.
- SQLite용 scripts/migrate_first_submission_sqlite.py 작성. 기본 read-only 검사, --apply는 새 백업 경로 필수. 중복 데이터가 있으면 중단. 시험용 DB에서 적용·중복 거부·원본 보존 검사 완료.
- app/db.py는 기존 DB에 최초 제출 유일 제약이 없으면 시작 시 마이그레이션 안내 오류로 중단한다. create_all이 기존 제약을 갱신했다고 오인하지 않기 위한 조치이다.
- sql/quiz_003_client_access.sql은 Supabase RLS 활성화와 anon/authenticated의 원본 테이블 직접 접근 차단을 준비한다. quiz_sets JSON에는 정답이 있으므로 ‘본인 세트면 원본 SELECT 허용’ 정책을 만들지 않았다. 본인 조회는 인증된 서버 API로 제공한다.
- RLS SQL 적용 전 실제 서버의 DB 역할/권한과 학습노트 등 다른 사용처를 통합 담당자가 확인해야 한다. 서버 자격증명은 프론트에 노출하지 않는다.
- scripts/check_postgres_requirements.py는 배포 서버의 환경변수를 사용하여 역할·RLS·유일 제약·중복 건수만 읽기 전용 검사한다. 이번에는 운영 DB에서 실행하지 않았다.
- 에이전트가 운영 DB에 직접 접속하거나 기존 기록을 삭제하지 않았다. 이후 사용자가 Supabase SQL Editor에서 마이그레이션을 실행하고 캡처를 제공했다. 중복 제출 조회 0건 및 uq_quiz_submissions_quiz_set / UNIQUE (quiz_set_id) 존재를 캡처로 확인했다.
- 사용자 제공 조회 결과에서 quiz_sets·quiz_submissions의 RLS=true, RLS 정책 0건, anon/authenticated의 SELECT·INSERT·UPDATE·DELETE 기본 권한=true를 확인했다. 이는 운영 역할 기반 실제 접근 거절 시험이 아니다. quiz_003_client_access.sql은 아직 실행하지 않았다.
- 운영 PostgreSQL에서 실제 동시 제출·rollback 복구 및 실제 로그인 접근 제어는 미검증이다.

## 다른 모듈이 필요한 미완료 요구

1. 공통 LLM 호출 모듈: 현재 연결 폴더에는 챗봇·팀 공통 모듈이 없으므로 전용 OpenAI 클라이언트 유지. 존재하지 않는 공통 모듈을 새로 만들어 ‘공유 완료’로 표기하지 않았다. generator 주입 경계를 통해 실제 공통 구현을 연결할 수 있다.
2. 채점 결과·개념 상태·스테이지 이벤트의 단일 트랜잭션: 학습 관리 내부 저장소가 이 checkout에 없으므로 구현하지 않았다. 기존 결과 선저장·함수 보고를 유지하고 보고 오류 시 결과를 보존한다. 재전달 큐를 구현한 것으로 주장하지 않는다.
3. 실제 같은 개념의 챗봇 복귀·학습 완료→퀴즈 연결·실제 로그인·후속 상태·보상 반영: 사이트 복구 후 공동 통합시험 필요. URL 정보와 목적지 주입만으로 연결 완료라고 주장하지 않는다.
4. 현재 Stage·학습 완료 자격 판단은 챗봇/학습 관리의 계약에 의존한다. 퀴즈 모듈이 없는 학습 관리 상태를 추측하지 않는다.
5. 확장 요구(별도 LLM 교차검증·난이도 자동 조절·학습 분석)는 구현하지 않음.

- 이탈 복원: 선택 답안·현재 문항·제출 키의 같은 탭 새로고침 복원 추가. sessionStorage이므로 탭 종료/다른 장치 복원은 보장하지 않는다.
- 로그: 생성은 processing 저장 이후부터, 채점은 답안 처리부터 저장까지. 학습 관리 보고 및 전체 HTTP 응답 시간과 구분.
- QR-02의 운영 유일 제약은 사용자 캡처로 적용 확인. 운영 동시 제출은 별도 시험. 공통 LLM·단일 트랜잭션 및 실제 로그인/RLS 접근 시험을 완료로 올리지 않는다.
- 별도 실행 기록인 11월 9일/이전 11월 10일 40초 코드 검사와 이번 30초 코드 검사를 구분.
